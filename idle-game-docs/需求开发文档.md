# 勇士文字放置游戏需求开发文档

**版本：** v0.1  
**状态：** 已确认的 MVP 需求  
**平台：** 桌面与手机浏览器  
**存档方式：** 浏览器本地存档，支持 JSON 导入与导出

## 1. 产品概述

本项目是一款以文字、数据面板、战斗日志和简笔图标为主要表现形式的单人网页放置游戏。玩家扮演一名勇士，在怪物区域中战斗、积累经验和怪物材料；再通过伐木、钓鱼、采矿补充基础资源，制作装备、药水与自动化设施，最终挑战更强的怪物。

核心循环如下：

```text
打怪获得经验、怪物材料与少量金币
  -> 采集木材、鱼类、矿石等基础资源
  -> 制作装备、治疗药水和自动化设施
  -> 提升属性、解锁区域、挑战更强怪物
```

首版定位为可玩原型，重点验证成长、资源调度与自动化解锁是否有趣。新玩家应在约 45-60 分钟内解锁第一批自动化能力，并理解三线挂机的长期目标。

## 2. 目标与范围

### 2.1 MVP 目标

- 让玩家在 1 分钟内开始第一场自动战斗。
- 建立“战斗、采集、制作”三者互相依赖的资源循环。
- 提供有风险但不会过度挫败的战斗失败规则。
- 从前期手动生产过渡至后期自动化并行生产。
- 在关闭网页后保留进度，并提供清晰的离线收益反馈。

### 2.2 MVP 内容基线

| 内容 | 数量 / 规则 |
| --- | --- |
| 勇士 | 1 名，无职业分支 |
| 战斗区域 | 5 个，按顺序解锁；每区 1 个主怪物 |
| 采集点 | 3 个：伐木、钓鱼、采矿 |
| 装备 | 12 件装备模板，4 个等级，每级武器/护甲/饰品各 1 件；制作时属性在模板范围内随机生成 |
| 装备槽 | 武器、护甲、饰品 3 槽 |
| 核心属性 | 攻击、防御、生命、速度 |
| 货币 | 材料为主，少量金币用于修理等功能 |
| 消耗品 | 治疗药水 |
| 自动化设施 | 自动伐木、自动钓鱼、自动采矿、自动工坊 |

### 2.3 MVP 不包含

- 账号、云存档、后端服务、排行榜或多人功能。
- 职业、技能树、元素克制、暴击、闪避、随机词缀装备。装备允许在预设属性范围内随机生成数值，但不引入随机词缀或额外词条。
- 商店经济、广告、付费、交易或拍卖。
- 主线任务、大量剧情、复杂地图、角色动画或特效。
- 自动喝药功能；该功能作为后续可解锁内容预留。

## 3. 核心活动与阶段规则

### 3.1 前期：单活动槽

自动化设施尚未完成时，战斗、采集、制作共用一个活动槽：

- 同一时刻仅允许一项活动运行。
- 启动新活动时，当前活动立即暂停，已完成的计时进度必须保留。
- 战斗是持续自动进行的活动，可在关闭页面后进行离线结算。
- 采集和制作均由玩家点击启动，一次只进行一个计时行动。
- 前期采集和制作在关闭页面期间不推进、不结算。

### 3.2 后期：自动化与三线并行

自动化设施以配方制作获得，且永久解锁。相应设施完成后，其活动可循环自动运行：

- 自动伐木、自动钓鱼、自动采矿分别让对应采集点可自动循环。
- 自动工坊让指定制作配方可自动循环。
- 已具备自动化能力的战斗、采集、制作可使用独立活动队列并行运行。
- 完成全部采集自动化与自动工坊后，战斗、采集、制作三线可同时运行。
- 自动化活动可独立暂停、恢复、切换目标；可用于离线结算。

### 3.3 计时与操作

前期手动采集和制作采用“点击启动，计时完成”模式，不是即时点击产出：

| 行动 | 建议基础耗时 |
| --- | --- |
| 伐木 | 10 秒 |
| 钓鱼 | 15 秒 |
| 采矿 | 20 秒 |
| 装备制作 | 15-60 秒，随等级提升 |
| 药水 / 设施制作 | 10-45 秒 |

具体时长、产出和配方成本必须配置化，允许在试玩后调整。页面刷新、切换标签和重新打开页面后，未完成的在线计时进度必须被正确恢复。

## 4. 战斗系统

### 4.1 区域与目标

- 5 个区域依次解锁，每个区域配置一个主怪物。
- 玩家选择已解锁区域并开始战斗后，勇士连续挑战该区域同一种怪物。
- 当前区域首次击败、累计击败次数与区域解锁条件可作为后续内容扩展点；MVP 只要求等级与装备门槛推动区域推进。
- 怪物掉落经验、怪物材料和少量金币。掉落表按区域配置。

### 4.2 自动战斗

战斗采用按攻击间隔结算的自动对砍：

1. 勇士和怪物均拥有攻击、防御、生命、速度属性。
2. 双方按各自攻击间隔自动攻击。
3. 速度仅影响战斗攻击间隔，不影响采集和制作效率。
4. 目标生命降至 0 时，当前场次结束。
5. 勇士获胜后，结算经验、材料和金币，并立即开始下一场。
6. 玩家可随时暂停、撤退，或在前期切换至采集/制作。

默认公式可作为首版实现基线，后续允许调参：

```text
单次伤害 = max(1, 攻击 - 防御)
攻击间隔 = max(0.5 秒, 2.5 / (1 + 速度 / 100))
```

当攻击事件同一时刻发生时，勇士攻击先结算。

### 4.3 生命、脱战与战败

- 勇士生命跨战斗场次持续保留，获胜后不自动回满。
- 切换至采集或制作时，战斗立即暂停。
- 未处于战斗时，勇士每 10 秒恢复最大生命的 1%，至少恢复 1 点。
- 玩家可以手动使用治疗药水恢复生命，治疗不超过最大生命。
- 生命降至 0 时，勇士立即撤退，当前战斗停止，生命设为 1。
- 每场战斗结束后（无论勇士胜利或战败），所有已装备物品均扣除耐久；MVP 默认每件扣除 1 点，具体扣除量必须配置化。
- 战败不再额外扣除一整套装备耐久；战败仍会停止当前战斗并将生命设为 1。
- 发生战败时不扣除已获得的材料、经验或金币。

### 4.4 治疗药水

- 治疗药水由钓鱼材料与怪物材料制作。
- MVP 中只能由玩家手动点击使用。
- 药水恢复量、制作耗时与成本由配方配置决定。
- 需要预留自动喝药的解锁状态和 UI 扩展位置，但 MVP 不实现该功能。

## 5. 装备、耐久与库存

### 5.1 装备与属性

- 装备分为武器、护甲、饰品三个槽位。
- 12 件装备是固定名称、槽位和属性范围的装备模板；每次制作时，在模板规定的最小值和最大值之间生成该件装备的实际属性。
- 随机属性只影响预设属性的数值，不改变装备名称、槽位、等级或可用配方。
- 装备生成后必须保存实际属性数值，装备查看面板需要显示本次生成结果及其范围。
- 装备可提供攻击、防御、生命和速度中的一个或多个属性。
- 玩家可装备、卸下、查看属性和耐久。
- 装备制作是主要装备来源；怪物主要掉落制作材料，而非随机掉装。

### 5.2 耐久与破损保护属性

每件装备需要包含最大耐久、当前耐久、完整属性和破损保护属性。

- 每场战斗结束后，所有已装备物品按配置扣除耐久；胜利和战败均消耗耐久。
- 一场战斗只触发一次耐久扣除，不能因日志刷新、页面刷新或离线重复结算而重复扣除。
- 耐久大于 0 时，装备提供完整属性。
- 耐久为 0 时，装备进入破损状态，仍保留配置的保护属性，但不再提供完整属性。
- 示例：一把武器完整攻击为 10，破损保护攻击为 3。其耐久归零后，只提供 3 点攻击。
- 任意已装备物品耐久归零后，装备进入破损保护状态，但自动战斗仍可启动并继续运行；战斗面板和装备栏必须持续显示破损警告。
- 修理可针对单件装备或一键修理全部装备；修理恢复至最大耐久，并消耗金币与对应材料。

### 5.3 背包

- 材料库存无限，不需要容量管理。
- 装备库存固定为 12 格。
- 制作新装备前必须确认存在空位。
- 装备栏满时，不允许静默覆盖或丢弃装备；提示玩家分解已有装备。
- 分解装备返还部分制作材料，不引入装备出售系统。

## 6. 资源、制作与自动化

### 6.1 资源分工

| 来源 | 主要产物 | 核心用途 |
| --- | --- | --- |
| 战斗 | 经验、怪物材料、少量金币 | 区域推进、高阶装备、药水、设施与修理 |
| 伐木 | 木材类材料 | 装备、设施与工坊相关配方 |
| 钓鱼 | 鱼类材料 | 治疗药水及部分装备配方 |
| 采矿 | 矿石类材料 | 武器、护甲和高阶设施 |

具体材料名称、数量、掉率与配方消耗均由数据配置定义；必须保证每一类活动都对至少一个关键配方有直接贡献。

### 6.2 制作类别

- 装备：制作并装备以提升战斗属性。
- 治疗药水：保障持续战斗和应对失败风险。
- 自动化设施：永久解锁采集和制作自动化，是中期目标。
- 修理：消耗金币与材料，恢复装备完整属性。

## 7. 离线收益与存档

### 7.1 离线结算

- 使用 `lastActiveAt` 记录最后一次有效保存时间。
- 最大离线结算时间为 8 小时。
- 前期只结算正在运行的战斗活动。
- 自动化设施解锁后，结算对应的自动采集或自动制作活动。
- 离线结算只计算自上次保存到当前打开时间之间的增量；重复刷新或重复打开不得重复发放。
- 重新进入游戏时展示收益摘要，包括离线时长、战斗次数、经验、金币、材料、制作物和中断原因。
- 若离线期间因生命归零、库存限制或材料不足而无法继续，结算应在该时刻停止并说明原因；装备破损本身不能阻止战斗继续。

### 7.2 本地存档

- 任何核心状态变化后自动保存，包括资源变化、活动状态、战斗结果、装备操作和解锁状态。
- 页面卸载前再次尝试保存。
- 提供 JSON 格式的手动导出和导入。
- 提供明确的重置存档功能，执行前要求二次确认。
- 导入存档时校验版本、必需字段、字段类型、材料/金币非负、装备 ID 合法、耐久范围合法。
- 不合法或损坏的存档不得覆盖当前有效存档，并需给出可理解的错误提示。

建议的存档概念结构：

```text
SaveData
  schemaVersion
  savedAt
  lastActiveAt
  player: 等级、经验、生命、金币、基础属性
  materials: 材料 ID -> 数量
  equipment: 装备栏、已装备槽位、耐久
  activities: 战斗/采集/制作的目标、进度、运行状态、自动化状态
  unlocks: 区域、配方、设施
  settings: 自动化开关及用户设置
  eventLog: 最近战斗、制作和离线结算记录
```

## 8. 界面与交互

采用单页工作台布局，用标签切换主要系统，适配 360px 宽度手机屏幕和常见桌面宽度。

### 8.1 顶部状态区

- 勇士等级和经验进度。
- 当前生命 / 最大生命。
- 金币数量。
- 当前活动摘要和运行状态。
- 装备破损或低耐久提示。
- 离线收益摘要入口。

### 8.2 战斗标签

- 区域列表、解锁条件与当前选择。
- 怪物属性、掉落预览和战斗状态。
- 勇士当前属性、装备状态和生命。
- 开始、暂停、撤退、手动喝药操作。
- 按时间顺序展示最近战斗日志。

### 8.3 采集标签

- 三个采集点的产物、单次耗时、解锁及自动化状态。
- 前期的单次开始、等待进度和领取状态。
- 后期的自动运行、暂停、切换和离线资格状态。

### 8.4 制作标签

- 装备、药水和设施配方分类展示。
- 配方成本、制作时间、材料缺口和解锁条件。
- 当前制作进度、自动工坊状态与队列状态。
- 装备满栏时给出明确阻断提示和前往背包操作。

### 8.5 背包标签

- 全部材料及数量。
- 12 个固定装备栏。
- 装备完整属性、当前耐久、破损保护属性和装备状态。
- 装备、卸下、分解、单件修理、一键修理操作。

### 8.6 视觉要求

- 使用简洁冒险日志风格：面板、表格、日志、徽标和简笔线性图标为主。
- 使用颜色区分运行、暂停、完成、锁定、材料不足、低生命和破损状态。
- 不需要复杂插画、角色动画或 3D 场景。
- 文字、按钮和状态信息在手机、桌面下均不得重叠或溢出。
- 核心操作应同时适合鼠标、触控和键盘使用。

## 9. 数据与实现约束

当前不锁定具体前端框架或游戏引擎，但实现必须满足以下边界：

- 所有区域、怪物、材料、装备、配方、掉落、行动时长和数值公式均数据驱动，不能散落硬编码在界面事件中。
- 游戏状态、离线结算、活动计时和存档序列化应独立于 UI 渲染层。
- 资源数量、经验、耐久和活动进度必须防止出现负数或重复结算。
- 数值需要允许快速调优；怪物属性、掉落量、配方成本和自动化门槛不应改代码才能调整。
- 首版为纯客户端单机应用，不请求后端服务。

建议至少定义以下概念模型：

| 模型 | 职责 |
| --- | --- |
| `PlayerState` | 等级、经验、当前生命、金币、汇总属性 |
| `EquipmentItem` | 装备模板 ID、槽位、等级、实际生成属性、属性范围快照、保护属性、当前/最大耐久 |
| `MaterialInventory` | 材料 ID 与数量映射 |
| `ActivityState` | 活动类型、目标、进度、运行状态、自动化状态 |
| `ZoneConfig` | 区域、怪物属性、掉落与解锁条件 |
| `RecipeConfig` | 配方输入、产物、耗时与解锁条件 |
| `UnlockState` | 已解锁区域、配方和自动化设施 |
| `SaveData` | 可导入导出的完整版本化存档 |

## 10. 验收标准与测试场景

### 10.1 核心可玩性

- 新存档可在 1 分钟内发起第一场战斗。
- 玩家能通过战斗、采集和制作获得更高属性装备，并解锁更强区域。
- 普通新玩家可在约 45-60 分钟内取得首次自动化能力。

### 10.2 活动与自动化

- 未解锁自动化时，任意时刻只能运行一项活动。
- 切换活动后，旧活动立即暂停，进度不丢失。
- 前期战斗支持离线结算；前期采集/制作离线不产生额外进度。
- 自动化解锁后，对应活动可循环运行并参与离线结算。
- 全部自动化设施解锁后，战斗、采集、制作可并行运行和独立暂停。

### 10.3 战斗、生命与耐久

- 攻击、防御、生命、速度均能按规则影响战斗结果。
- 每次制作装备均在对应模板的属性范围内生成实际属性；生成值和范围均可在装备面板查看。
- 速度只改变攻击间隔。
- 生命跨战斗保存，退出战斗后按规则缓慢恢复。
- 手动喝药不能将生命恢复到最大值以上。
- 每场战斗结束后，所有已装备物品只扣除一次耐久，胜利和战败均生效。
- 战败后生命变为 1，自动战斗停止；战败不得额外重复扣除耐久。
- 耐久为 0 的装备只提供保护属性。
- 任一已装备物品耐久为 0 时，仍可启动或继续自动战斗，但只提供破损保护属性，并显示破损警告。
- 修理后装备恢复最大耐久和完整属性。

### 10.4 资源、制作与库存

- 制作配方正确扣除材料并在完成时给出产物。
- 材料不足时不得启动制作。
- 装备栏满时不得制作新装备或无提示丢弃旧装备。
- 分解装备只返还配置的材料数量。
- 修理正确扣除金币和材料，资源不会变为负数。

### 10.5 存档与离线结算

- 自动保存后刷新页面，游戏状态可正确恢复。
- 离线结算最多计算 8 小时。
- 重复刷新不会重复领取离线收益。
- 离线期间活动遇到停止条件时，收益在停止点终止并显示原因。
- 导出的 JSON 可导入并恢复等价的游戏状态。
- 损坏、版本不兼容或字段非法的 JSON 不会覆盖当前存档。

### 10.6 界面适配

- 在桌面与最小 360px 宽度下，主要按钮、数值和日志均可读且不重叠。
- 活动运行、暂停、锁定、完成、低生命、材料不足和装备破损均有清晰状态提示。

## 12. 已确认的默认决策

- 首版优先文字信息密度和清晰反馈，不追求复杂视觉表现。
- 战斗是主要挂机线；采集和制作先由手动计时操作驱动，再通过设施转为挂机。
- 战斗失败有明确代价；装备破损仍保留部分保护属性且不阻止继续战斗，玩家可自行决定何时修理。
- 材料是主经济资源，金币只承担修理等辅助消耗。
- 数值平衡在开发和试玩中调优，不改变本文定义的活动、失败和存档规则。
